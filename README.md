# Database Cleaner для Home Assistant

Кастомная интеграция: анализ базы recorder (SQLite) и — в следующих версиях — её безопасная очистка.
Подробный план: [docs/implementation-plan.md](docs/implementation-plan.md).

> **Версия 0.1.0 — только чтение.** Интеграция открывает базу в режиме `mode=ro` + `PRAGMA query_only`
> и физически не может в неё записать. Удаление, бэкап и VACUUM появятся в следующих фазах.

## Что умеет

- **Панель в боковом меню** (только для администраторов), в цветах активной темы HA:
  - **Обзор** — размер базы и WAL, свободное место, куда уходит место по таблицам, диапазоны дат.
  - **Статистика** — долговременная статистика по категориям (сироты, отключённые, исключённые фильтром,
    остановленные, живые…), группировка по устройству / интеграции / единице, периоды, поиск.
  - **Состояния** — кто сколько пишет в `states` за 1 ч / 24 ч / 7 д, группировка по сущности, устройству,
    интеграции, домену, зоне; топ событий.
  - **Диагностика** — нагрузка записи, свежесть данных, очередь recorder, время пробных запросов,
    проверка целостности (`quick_check`).
- **Сенсоры**: топ-N «болтливых» сущностей за 24 ч (счётчики за час, сутки и всё окно), записей за час
  и за сутки, размер базы и WAL, свободное место, строк статистики, очередь recorder, время пробного запроса.
  Сенсоры не задают `state_class`, поэтому не создают новую долговременную статистику.

## Установка (вручную)

1. Скопируйте папку `custom_components/database_cleaner` в `/config/custom_components/`
   (через Samba, SSH или File editor).
2. Перезапустите Home Assistant.
3. **Настройки → Устройства и службы → Добавить интеграцию → Database Cleaner.**
4. В боковом меню появится пункт **Database Cleaner**. Параметры (окна, периоды, размер топа,
   число сенсоров, интервал обновления) — кнопка «Настроить» у интеграции.

Через HACS: добавьте репозиторий как пользовательский (тип «Интеграция»).

Требования: Home Assistant 2026.10+ (проверено на 2026.10.4), recorder на SQLite.

## Разработка

```text
custom_components/database_cleaner/
  engine/        чистый Python без зависимостей от HA: SQL-запросы, категории, кэш
  frontend/      panel.js — веб-компонент без сборки и внешних зависимостей
  *.py           обвязка HA: config flow, WebSocket-команды, сенсоры, панель
dev/             локальный просмотр панели на копии базы
tests/engine/    тесты движка (обычный pytest, Python 3.12+)
tests/integration/  тесты в настоящем Home Assistant (pytest-homeassistant-custom-component)
```

Приватная копия базы и `.storage` кладётся в `gitignore/` (папка игнорируется git).

Тесты движка:

```bash
python -m pytest tests/engine
```

Тесты интеграции (нужно окружение с HA, на Windows — с заглушками `fcntl`/`resource` в `.venv`):

```bash
uv venv .venv --python 3.14
```

```bash
uv pip install --python .venv/Scripts/python.exe pytest-homeassistant-custom-component home-assistant-frontend
```

```bash
.venv/Scripts/python.exe -m pytest tests/integration
```

Просмотр панели на копии базы (откройте http://127.0.0.1:8765/):

```bash
python dev/devserver.py
```
