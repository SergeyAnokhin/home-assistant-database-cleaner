# Database Cleaner для Home Assistant

Кастомная интеграция: анализ базы recorder (SQLite), поиск неиспользуемой статистики, бэкап базы
и безопасное удаление выбранной долговременной статистики.
Подробный план: [docs/implementation-plan.md](docs/implementation-plan.md).

> **Версия 0.3.0.** Анализ читает базу через отдельное соединение только для чтения. Любые изменения —
> удаление статистики, сжатие (VACUUM), восстановление — идут только через очередь задач самого recorder,
> небольшими порциями, после проверок и свежего проверенного бэкапа. Статистика панели «Энергия» не удаляется.

## Что умеет

- **Панель в боковом меню** (только для администраторов), в цветах активной темы HA:
  - **Обзор** — размер базы и WAL, свободное место, куда уходит место по таблицам, диапазоны дат.
  - **Кандидаты** — вердикт по каждой статистике с учётом того, где она используется (энергия, дашборды,
    автоматизации и скрипты — включая шаблоны, сцены, группы, люди, хелперы и YAML-файлы конфига): можно
    удалить / нигде не используется / проверить / используется / защищено. Выбор флажками, список, YAML для `recorder: exclude`
    и **удаление выбранного** (с проверками и вводом слова-подтверждения).
  - **Проблемы** — то, что Home Assistant сам считает неправильным в статистике (`units_changed`,
    `state_class_removed`, `mean_type_changed`, `no_state`, исключено из recorder… — как в «Инструменты
    разработчика → Статистика», с пометкой, открыта ли задача в «Исправлениях») и наши проверки: есть
    `state_class`, но статистика не пишется; единица или `state_class` не подходят к классу устройства;
    метаданные не совпадают со `state_class`; накопленная сумма `total_increasing` уменьшается (в «Энергии»
    появляется отрицательное потребление); используемая сущность недоступна. Проблемы важных сущностей
    (Энергия, дашборды, автоматизации, YAML) идут первыми. Вкладка только показывает и подсказывает, что делать.
  - **Обслуживание** — бэкап базы, сжатие (VACUUM), ход текущего задания с отменой, журнал, список бэкапов,
    архивы отмены с восстановлением «на лету».
  - **Статистика** — долговременная статистика по категориям (сироты, отключённые, исключённые фильтром,
    остановленные, живые…), группировка по устройству / интеграции / единице, периоды, поиск.
  - **Состояния** — кто сколько пишет в `states` за 1 ч / 24 ч / 7 д, группировка по сущности, устройству,
    интеграции, домену, зоне; топ событий.
  - **Диагностика** — нагрузка записи, свежесть данных, очередь recorder, время пробных запросов,
    проверка целостности (`quick_check`).
- **Сенсоры**: топ-N «болтливых» сущностей за 24 ч (счётчики за час, сутки и всё окно), записей за час
  и за сутки, размер базы и WAL, свободное место, строк статистики, очередь recorder, время пробного запроса,
  число проблем статистики по версии Home Assistant.
  Сенсоры не задают `state_class`, поэтому не создают новую долговременную статистику.

## Как устроено удаление

1. **Проверки:** HA работает, миграция не идёт, схема recorder проверена (≤ 53), очередь recorder в норме,
   хватает места, `quick_check` = ok.
2. **Защита «Энергии»:** ссылки пересчитываются на сервере; статистику панели «Энергия» удалить нельзя.
3. **Бэкап** базы (SQLite Online Backup API, без остановки HA) с проверкой `integrity_check`, если нет
   свежего (24 ч по умолчанию). Хранятся 2 последних, по умолчанию в `/share/database_cleaner/backups`.
4. **Порции** до 50 000 строк: строки порции пишутся в архив отмены (fsync), затем удаляются через
   `recorder` (`async_clear_statistics`). Между порциями — пауза, проверка очереди и возможность отмены.
5. **Сжатие** (по желанию): `recorder.purge` с `repack: true` — VACUUM внутри recorder.

**Отмена удаления:** вкладка «Обслуживание» → «Архивы отмены» → «Восстановить». Строки возвращаются через
официальный импорт статистики, без остановки HA (архивы хранятся 30 дней).

**Полное восстановление файла** (если что-то пошло совсем не так) требует остановить Core:
`ha core stop` → переименовать `home-assistant_v2.db` (и `-wal`, `-shm`) → положить бэкап на его место под
именем `home-assistant_v2.db` → `ha core start`.

**Где ищутся ссылки на сущность:** панель «Энергия», все дашборды, автоматизации и скрипты (включая шаблоны),
сцены, группы, люди, хелперы из интерфейса и текст всех `*.yaml` в папке конфига (комментарии и `secrets.yaml`
пропускаются; `custom_components`, `.storage`, `www`, `esphome`, `backups` тоже). Не видны Node-RED, AppDaemon и
внешние системы (Grafana, InfluxDB) — это написано в интерфейсе.

> ⚠️ Удаление статистики живого сенсора не мешает ему копить её заново. Чтобы сенсор перестал писаться,
> добавьте его в `recorder: exclude` (кнопка YAML на вкладке «Кандидаты»).

## Установка (вручную)

1. Скопируйте папку `custom_components/database_cleaner` в `/config/custom_components/`
   (через Samba, SSH или File editor).
2. Перезапустите Home Assistant.
3. **Настройки → Устройства и службы → Добавить интеграцию → Database Cleaner.**
4. В боковом меню появится пункт **Database Cleaner**. Параметры (окна, периоды, размер топа,
   число сенсоров, интервал обновления) — кнопка «Настроить» у интеграции.

Через HACS: добавьте репозиторий как пользовательский (тип «Интеграция»).

Требования: Home Assistant 2026.10+ (проверено на 2026.10.4), recorder на SQLite.

## Разработка

```text
custom_components/database_cleaner/
  engine/        чистый Python без зависимостей от HA: SQL-запросы, категории, кэш
  frontend/      panel.js — веб-компонент без сборки и внешних зависимостей
  *.py           обвязка HA: config flow, WebSocket-команды, сенсоры, панель
dev/             локальный просмотр панели на копии базы
tests/engine/    тесты движка (обычный pytest, Python 3.12+)
tests/integration/  тесты в настоящем Home Assistant (pytest-homeassistant-custom-component)
```

Приватная копия базы и `.storage` кладётся в `gitignore/` (папка игнорируется git).

Тесты движка:

```bash
python -m pytest tests/engine
```

Тесты интеграции (нужно окружение с HA, на Windows — с заглушками `fcntl`/`resource` в `.venv`):

```bash
uv venv .venv --python 3.14
```

```bash
uv pip install --python .venv/Scripts/python.exe pytest-homeassistant-custom-component home-assistant-frontend
```

```bash
.venv/Scripts/python.exe -m pytest tests/integration
```

Просмотр панели на копии базы (откройте http://127.0.0.1:8765/):

```bash
python dev/devserver.py
```
